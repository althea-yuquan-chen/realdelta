# plan --from: validation protocol (fixed before any run, 2026-11-23)

Question. A user gives one baseline result file. Can a per-case posterior plan estimate the power that their
fixed suite would actually have, well enough to answer "how many trials do I need"?

Why this design. The beta-binomial fit failed on most near-100% files
(plan_from_fit_diagnostic_20261123.txt: Beta(20,1), 10 cases x 3 trials, 9% fitted). Per-case posteriors never
fail and keep each case's identity (the suite scope's question).

## Methods compared (all fixed now)
- P-Jeffreys: each case's rate drawn per simulation from Beta(x_i + 0.5, n_i - x_i + 0.5).
- P-uniform: Beta(x_i + 1, n_i - x_i + 1).
- Plug-in: each case's rate = x_i / n_i (baseline for comparison only).
For each simulation: draw rates (posterior methods), then run the same break-k or shift comparison as
`plan_trials` (the candidate breaks k randomly chosen cases or shifts all by delta, clipped), detection rule and
`delta_interval` unchanged.

## Ground truth
True suites: rates drawn once per suite from Beta(20,1), Beta(4,2), Beta(0.5,0.5); m in {10, 30} cases. The
user's file: one baseline run of that suite with n_obs in {3, 5} trials per case. True power: the same
comparison simulated from the true rates (500 simulations). Changes: break k = 3 (k = 2 when m = 10) and shift
delta = -0.05. Planned trials n_plan in {n_obs, 10}.
Per setting (3 distributions x 2 m x 2 n_obs = 12): 20 true suites, one file each; estimated power from each
method with 200 simulations. Seeds: base 20261124, fixed per (setting, suite, method) as recorded in the script.

## Outcomes and decision rule
Per setting, change and n_plan: mean error (estimated - true power) and mean absolute error over the 20 suites,
with Monte Carlo SE. Monte Carlo noise alone: SE of a 200-simulation power is at most 0.035.
A posterior method is acceptable if, in every cell, |mean error| <= 0.10 and MAE <= 0.15. Among acceptable
methods, ship the one with the smaller worst-cell MAE; ties go to the one whose errors are more often negative
(underestimating power is the safer mistake for planning). If neither is acceptable, nothing ships; the result
is reported and the design is revisited. Plug-in is reported for comparison and cannot be chosen.
All output is committed (or kept in notes) as produced; the rule above is not changed after seeing results.

## Not claimed
The result describes these synthetic settings only. It is not a coverage claim and does not touch the gated
grid.

## Revision 1 (after review, before any run; overrides the text above where they differ)
Methods (all fixed now; any method added after seeing results is post-hoc, rerun with new seeds and labeled so):
- P-Jeffreys, P-uniform as above.
- P-pooled: per-case posterior Beta(x_i + c*pbar, n_i - x_i + c*(1 - pbar)), pbar = (X + 0.5)/(N + 1) over the
  whole file, c = 2. Needs no fit and cannot fail.
- Plug-in: comparison only.
Settings: true rates from Beta(20,1), Beta(4,2), Beta(0.5,0.5), and Mix (80% of cases exactly 1.0, 20%
Uniform(0.3, 0.9)); m in {10, 30}; n_obs in {3, 5}. 50 true suites per setting, one observed file each.
Changes: break k in {1, 3} (k = 2 instead of 3 when m = 10), the k cases chosen at random in each simulation
(target: "k randomly chosen cases break"); shift delta = -0.05. n_plan in {n_obs, 5, 10} (deduplicated).
Simulation: realdelta's own internal _delta_interval (the code path plan_trials uses) on count arrays. True power
and true false-alarm rate: 2000 simulations from the true rates. Estimates: 200 simulations per method; within a
suite all methods share the observed file and the same random stream for trial outcomes (paired comparison).
A cell = (setting, change, n_plan). For each cell and method: mean error (estimate - truth), MAE, 90th percentile
of absolute error, over the 50 suites; same for the false-alarm rate.
Decision cells: cells whose mean true power is in [0.2, 0.9]. A pilot that computes true power only (no method)
runs first to list them; the list is saved before the main run. At least 8 decision cells are required, else
the validation is void and nothing ships.
Acceptable method: in every decision cell, mean error in [-0.10, +0.05] (overestimating power is the costlier
mistake) and MAE <= 0.15; and in every cell, the false-alarm estimate's mean error within +-0.05.
Choice: among acceptable methods, the smallest worst-decision-cell MAE; differences under 0.02 are ties, broken
by the more negative mean error (safer), then by simplicity (P-Jeffreys, P-uniform, P-pooled).
Partial pass (acceptable in some decision cells only): nothing ships this round; the result is reported.
Secondary (reported, not decisive): agreement between the first n_plan reaching power 0.8 by estimate and by truth.
Not claimed: only n_plan <= 10, conf 0.95, equal trials per case, these synthetic settings; not a coverage claim.
Before the main run, this file's sha256 is recorded in the run output.

## Revision 2 (after review of Revision 1; before any run)
- Decision cells must cover the near-100% settings: Beta(20,1) and Mix each need at least 2 decision cells, at
  least one of them with n_obs = 3. With fewer, the validation is void. Because the pilot holds truth only (no
  method), the grid of k, delta and n_plan may then be adjusted once, written as Revision 3 and fixed before the
  methods phase runs.
- False-alarm check: cells are (setting, n_plan) (the null does not depend on the change); the estimate's mean
  error must be within +-0.03.
- Decisions use point estimates, with no Monte Carlo margin.
- Controls: an "Oracle" method that is given the true rates must have |mean error| <= 0.03 in every cell (checks
  that the truth and methods phases use the same comparison logic); a consistency check compares, for one
  setting, the internal _delta_interval path with plan_trials-style detection through the public delta_interval.
  Plug-in is the negative control; if it passes every criterion, the criteria's power to discriminate is
  questioned in the report.
- The secondary result (first n_plan reaching 0.8) is on the grid {n_obs, 5, 10} only.
